# 真实服务测试方案

## 授权与范围

用户已允许测试调用真实服务，要求 Key 从本地 `.env` 读取、不得上传 GitHub。该授权覆盖千问、MiniMax、智谱、Kimi、DeepSeek 的有限接口验证，不包含真实 Codex App 操作。

真实服务测试是独立的按需运行入口，不属于单元测试，不默认随普通测试、构建或 GitHub CI 执行。已提供独立测试命令，实测结果见 [实现验证记录](implementation-validation.md)。

- 上传 GitHub 前同时检查暂存文件和内容；忽略规则不能防止已跟踪文件或其他文件中的意外复制，不使用强制添加绕过规则。

## 测试方法

1. 先根据官方资料明确每家服务的端点、套餐、协议和模型；不能根据 Key 猜测计费入口。
2. 只向明确选定的供应商端点发送合成测试内容，不发送用户项目文件或会话历史。
3. 首轮每家选一个模型，验证最小文本输出、流式输出、无副作用虚拟函数调用和结果回传。
4. 每家首轮最多 5 个请求，每请求输出上限 256 tokens；若官方约束不允许该上限，先记录限制并调整测试预算，不静默放大。每请求设有限超时，默认不自动重试、不并发压测。
5. 遇到鉴权、权限、额度、套餐或模型错误时停止该服务，不轮询其他域名或盲试模型。失败不影响其他服务的独立结果。
6. 不启动 Codex App 或其 app-server/CLI，不读写真实 Codex 配置。转换器和路由使用内存调用；如后续需要端口级集成测试，另行明确其范围。

请求和输出上限用于控制规模，不是精确费用保证；推理 token 或供应商计费规则仍可能影响费用。避免重复执行已经得到明确结果的探测。

## 2026-09-16：独立压缩验收

用户明确要求使用 `.env` 验证真实请求和长上下文压缩，先不经过 Codex App。本轮另提供 `pnpm test:providers:compact --all`，直接测试注册表中五家供应商的默认模型和原生 Responses 地址，不启动本地网关，不读取系统凭据。

- 普通生成输出上限调整为 2,048 tokens，超时 120 秒；压缩超时 180 秒。压缩接口不发送未在契约中定义的 `max_output_tokens`，其输出由服务端控制。所有请求串行，无自动重试、无自动切换模型或套餐端点。
- 完整流程每家最多 9 个请求：文本、SSE、虚拟函数调用、结果回传、短上下文压缩和续接、长上下文基线、长上下文压缩和续接。依赖失败时跳过后续环节；鉴权、权限、额度和模型错误不触发其他端点探测。
- 本轮使用 129,841 字节、97 条消息的合成历史。六个随机校验值仅位于 assistant 历史前、中、后段，并包含一次旧值覆盖。续接问题和系统指令不包含答案。
- 返回 `response.compaction` 和非空 `encrypted_content` 只算接口形态通过；必须将完整 `output` 原样放进下一次 `/responses`，不补回原始历史、不使用 `previous_response_id`，并同时验证基线召回、续接召回和实际输入 token 减少。
- 追加诊断须明确记录原因和预算。本次对三家工具参数错误改用 `auto`；Kimi 回传也改用 `auto`。MiniMax 额外 3 个请求使用真实生成的历史和 `reasoning=high` 做对照，排查合成历史与推理开关因素。
- `--tools-auto <provider>` 只做工具调用和回传两个请求，均使用 `auto`；`--compact-control <provider>` 只做真实生成历史、压缩、续接三个请求，并在生成及续接时启用 `reasoning=high`。这些诊断参数不修改产品预设。
- 脱敏回执写入已忽略的 `reports/local/provider-compact-*.jsonl`，权限 0600；不保存输出正文、推理正文、加密压缩内容或原始请求。记录用量、状态、耗时、输出类型、哈希和断言结果。退出码 1 表示存在真实失败，不表示脚本未执行。

验收契约参考 [OpenAI Compaction](https://developers.openai.com/api/docs/guides/compaction)：保留并原样续接完整压缩窗口。真实结果见 [2026-09-16 直连验证](provider-live-validation-2026-09-16.md)。

## 结果与报告

### 默认普通摘要路径

`pnpm test:providers:summary --all` 独立验证 remote 关闭时的普通模型摘要能力。每家最多 3 次真实请求：原始历史基线、摘要、摘要续接；全部使用 `/responses` SSE，不发送 compaction_trigger，不调用 `/responses/compact`。每请求输出上限 2,048 tokens、120 秒超时，失败依赖步骤停止，无自动重试。

提示词及摘要前缀来自固定 `openai/codex rust-v0.149.0`，保存在测试专用 fixtures 中并附 Apache-2.0 许可证。续接采用更严格的“只保留摘要和新问题”，不回传原始历史、基线答案或 previous_response_id。六个随机值和旧值覆盖必须全部召回，且实际输入 token 必须减少。

这验证的是直连供应商的摘要生成和消费，不等同于安装中的 Codex 版本执行了自动触发、完整历史替换、持久化和恢复。真实 Codex App 仍不在本轮范围内。源码/模拟集成另行验证开关标记、默认值、普通摘要桥接和 remote V2 原生 JSON/SSE 透传。

每家记录：服务 ID、模型、协议、时间、测试类型、通过/失败/跳过、状态码、耗时和脱敏错误分类。真实响应中的错误文本可能回显凭据，必须经过脱敏后才可展示。

不保存原始认证头和请求转储；报告不得包含 Key 或用户 `.env` 内容。代码与合成样本可提交，包含本地凭据的文件不可上传 GitHub。

报告分别列出单元测试与真实供应商检查；接口检查通过仅证明此次端点/模型测试成功，不能写成 Codex App 端到端验证通过。
