# 当前单元测试方案

## 执行边界

本文件规定隔离单元测试的执行边界。用户已另行授权从本地 `.env` 读取 Key 调用真实服务，见[真实服务测试方案](provider-test-plan.md)；不要将联网检查混入单元测试。真实 Codex App、独立 app-server/CLI 和系统集成测试仍不在当前执行范围。

- 不启动、激活、退出、重启或控制用户正在使用的 Codex App。
- 不读取、备份、改写或恢复用户实际的 Codex home、配置、登录与会话。
- 不访问系统钥匙串或凭据管理器；不加载工作区 `.env` 或使用真实 Key。
- 不设置全局环境变量，不安装后台服务，不监听测试端口，不发送网络请求。
- 所有样本人工构造；所有写入限于测试创建的临时目录。
- 真实 App 测试须用户明确恢复后再安排；单元测试通过不表示 App 实机兼容已验证。

这些是当前研发测试约束。产品将来的“配置并打开 Codex”能力仍保留在需求中，通过替身先验证业务逻辑。

## 首批供应商覆盖

`qianwen`、`minimax`、`zhipu`、`kimi`、`deepseek` 五家全部纳入预设校验和适配测试。使用人工构造的凭据、模型能力与响应样本，分别检查预设字段、端点拼接、认证请求构造和协议选择；共享转换逻辑的通用边界用例无需机械复制五份。

本地 `.env` 已由用户提供对应的五个 `*_key` 变量。单元测试不自动加载、不尝试鉴权、不发送探测请求；真实服务测试通过独立入口运行。变量映射见[产品方案](../product-plan.md)，空模板见 [.env.example](../../.env.example)。

## 设计方式

1. 配置合并、目录生成、URL 规范化和协议转换优先写成纯函数，接收输入并返回结果。
2. 文件、凭据、HTTP、应用启动、时钟和端口检测通过显式接口注入。
3. 单元测试只注入内存替身；需要验证文件替换的用例显式传入独立临时根目录，禁止回退到默认 home。
4. 流式处理用内存字节流喂入数据，无需运行 HTTP 模拟服务器。
5. 单元测试入口不初始化 Tauri、不读取系统配置、不构造真实平台适配器。依赖缺失时直接失败，不使用生产默认值兜底。

## 必测行为

| 模块       | 关键断言                                                                           |
| ---------- | ---------------------------------------------------------------------------------- |
| 配置合并   | 保留注释与无关字段；语法错误不生成写入；重复应用结果稳定                           |
| 恢复计算   | 按字节恢复开启前的配置；后加配置先另存，再自动恢复，无需确认；不存在的原文件正确处理 |
| 写入事务   | 故障注入覆盖各阶段；临时目录中的恢复结果与 journal 一致                            |
| 地址解析   | 保留路径前缀；识别完整端点；不重复追加 `/v1`；拒绝循环代理目标                     |
| 模型目录   | schema 必填项、同名模型隔离、未知能力的保守策略、稳定别名                          |
| 路由       | 默认切换不改变旧 route revision；无匹配时报错；不跨服务混用缓存                    |
| 请求转换   | 文本、工具声明、工具结果、namespace/custom 映射及参数合法性                        |
| SSE        | UTF-8 跨块、工具参数跨块、并行工具、结束事件、错误事件、截断                       |
| 上下文桥接 | response/call ID 精确关联；路由隔离；缓存缺失明确失败                              |
| 验证流程   | 401/429 等不错误触发协议回退；取消后停止后续步骤；无效输入不写配置                 |
| 启动决策   | 未安装/未运行/运行中/待重载分支；只校验替身调用，不实际打开应用                    |
| 密钥与诊断 | 输出中不含测试密钥；日志只包含允许字段；凭据失败不降级明文                         |

复杂的工具转换必须以真实协议结构的合成样本断言语义，例如调用与结果的 ID 对应关系、正确的完成状态；不能只断言函数被调用或把实现输出保存为快照就当成正确。

## 实现顺序

1. 配置合并、URL 解析、目录生成。
2. 路由版本与会话隔离。
3. Responses/Chat 转换和内存 SSE。
4. 验证、保存、恢复、打开的应用状态逻辑。
5. 必要的前端表单组件单元测试，Tauri IPC 使用替身。

Rust 使用单元测试及临时目录依赖，前端使用 Vitest/Testing Library。运行 `pnpm test` 执行两组隔离测试；运行 `pnpm check` 检查桌面与官网类型。开启协调层使用 `activation::Runtime` 替身，凭据策略使用 `connections::Credentials` 替身，均不会构造真实平台适配器。

## 完成报告

每次报告实际测试命令、通过/失败/跳过数量和覆盖的行为。测试失败必须修复或说明具体阻断。单元测试和真实服务测试分别报告；仅在对应测试实际通过后作出结论，始终注明真实 Codex App 兼容性尚未验证。
