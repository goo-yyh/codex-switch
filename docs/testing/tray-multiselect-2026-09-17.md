# macOS 托盘连续多选验证

2026-09-17，使用 `apps/desktop/src-tauri/examples/tray-smoke.rs` 在本机 macOS 原生菜单中验证。

运行：`cargo run -p codex-switch-desktop --example tray-smoke`。从测试应用菜单的 `Open test tray` 打开托盘菜单，再进入「选择配置（可多选）」。测试程序复用正式托盘实现，仅提供内存中的 A/B/C 配置和临时配置目录；开启服务操作为拒绝执行的替身，不访问 Keychain、不启动路由或 Codex，也不读取正式应用的数据目录。

## 实现边界

- macOS 配置项使用原生复选框视图，点击不会结束菜单跟踪。
- 配置选择在原生点击回调中同步保存，沿用操作锁和服务开启时禁止修改的校验。不能经由会延迟到菜单关闭后处理的事件队列批量保存。
- 保留菜单对象，勾选变化原地更新；不重复设置未变化的托盘提示或调整状态栏尺寸。
- 其他平台保留原生菜单行为，本次没有验证其菜单保持展开能力。

## 验证结果

- 勾选 A、B，取消 A，再勾选 C：整个过程中菜单未收起；重新打开后保留 B/C。
- 最终版本增加模拟主面板刷新：每次勾选后主动调用正式 `tray::sync`。
- 在上述刷新条件下连续勾选 A/B/C、再连续取消 A/B/C，菜单仍保持展开；重开后全部未选，「开启 Codex Switch」禁用，服务仍关闭。
- 「退出应用」正常结束隔离程序。
- 托盘 3 项 Rust 测试通过，包含多选、取消、无效 ID、服务开启时拒绝变更及关闭后恢复选择。

本次不是对真实账户、网关或 Codex 客户端的联调验证。
