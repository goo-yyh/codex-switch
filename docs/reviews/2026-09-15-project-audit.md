# 全项目复查与系统设置风格改版

日期：2026-09-15。范围：React App、原生命令、配置与恢复、SQLite、网关、协议转换、官网文档和现有验证脚本。

本轮后半段按用户确认的「系统设置风格」重做 App。下面区分已经随 UI 修复的问题，以及代码审查中仍待处理的后端问题。

## 已修复

1. **保存成功、启用失败后重试使用旧连接 ID（P1）**：原先清空 Key 却保留原表单 ID，编辑密钥后重试可能复用旧凭据。现在立即采用保存返回的新连接，重试复用新 ID。新增模拟保存成功、端口占用失败、再次保存的回归测试。
2. **弹窗内操作失败看不到错误（P2）**：原先错误显示在遮罩后方主页面，并被对话框的可访问性隔离隐藏。现在在对话框内显示错误，执行中禁止关闭；新增失败删除回归测试。
3. **密钥显示状态跨编辑会话保留（P2）**：退出、切换服务、新增、编辑及保存后重置为隐藏；新增回归测试。
4. **长连接名挤出窗口（P2）**：合法的 100 字符名称曾令 800px 视口的页面宽度达到 1054px。现在限制文本容器宽度，省略显示并保留完整 title；浏览器实测恢复为 800px。
5. **首页仅打开 App，容易遗漏启用（交互优化）**：关闭状态明确显示「使用此连接并打开 Codex」，依次启用连接并打开；正在运行且待重载时继续使用确认弹窗。新增调用顺序测试。
6. **表单填完 Key 后改中转站地址会清空 Key（交互优化）**：将自定义地址移到 Key 之前，继续保留安全的换地址清空规则。
7. **页面切换继承滚动位置（改版验证发现）**：右侧内容独立滚动后，切换视图会归零，避免新页面标题被截掉。
8. **视觉结构**：移除大标题口号、装饰箭头、大面积渐变；采用浅灰侧栏、白色分组、细分隔线、小面积蓝色主操作。官网产品示意与设计规范同步。

## 仍待处理的代码问题

### P2：完整历史回放的等价表达会被重复拼接

位置：`crates/core/src/gateway.rs:160`、`:205`。

`same_history_item` 只去掉外层 id、status 和 message 类型，不能归一化字符串内容与文本块，也不能忽略内容块内的空 annotations。

隔离复现：先缓存字符串 user 输入和带空 annotations 的 assistant 输出；随后带 previous_response_id 回传语义相同的文本块历史与一个新 user 消息。期望 3 项，实际得到 5 项，重复加入了缓存历史。这是本地合成输入复现，未经过真实 Codex App。

建议：对支持的文本消息建立保守的语义比较，保留工具身份、图片及其他非文本字段的严格检查；补充字符串/文本块、空 annotations、真正新增输入的反例测试。

### P2：删除连接的数据库操作没有事务

位置：`crates/core/src/store.rs:36`；跨凭据库调用位于 `apps/desktop/src-tauri/src/main.rs:239`。

连接记录与 selected 设置由两条独立 DELETE 删除。隔离 SQLite 内存数据库中，通过触发器让第二条语句失败，第一条删除仍然保留：方法返回错误，但连接记录已丢失。原生命令还会先删除凭据，因此数据库失败时也存在凭据与元数据不一致的窗口。

建议：数据库内部使用事务；凭据库与数据库之间增加可恢复删除流程或补偿，分别覆盖每一步故障。不要只交换两个调用顺序，这不能解决跨存储原子性。

## 兼容性与维护优化

### P2：长历史会连同最近工具推理元数据一起丢弃

位置：`crates/core/src/gateway.rs:72`。

超过 1MiB 时整个 History 不缓存，包括较小的 calls 元数据。缓存容量是现有文档已说明的限制；本次发现的改进点是完整历史与工具元数据的容量耦合。

隔离复现：超过 1MiB 的历史加一个带 reasoning_content 的工具调用；完整回放调用时省略该元数据。enrich 返回成功，但无法补回 reasoning_content。若上游依赖该字段，可能造成后续工具轮次失败；真实服务影响尚未验证。

建议：为近期工具调用维护独立、有容量和过期限制的元数据缓存；无法恢复必需上下文时提供明确错误，不能虚构推理内容。

### P2：assistant 进度文本与紧随其后的工具调用分成两条消息

位置：`crates/core/src/protocol.rs:119`。

目前只合并已经带 tool_calls 的尾部消息，不合并前面的 assistant 文本。合成测试得到两条 assistant 消息，而合并表达只需要一条同时带 content 和 tool_calls 的消息。

参考的 CC Switch 固定版本 `06082e189d65e6d6dbadc35dacdac1ce6c79d89a` 中，`src-tauri/src/proxy/providers/transform_codex_chat.rs` 的 `flush_pending_tool_calls` 明确处理了这个情况，并说明分离的进度消息可能诱导模型只回复进度而不继续调用工具。参考来源是 `/tmp/codex-switch-cc-switch-reference` 的本地代码，未声称检查了最新版本。

建议：按 assistant 回合边界合并进度与工具调用，同时保留 reasoning、多个调用及工具结果顺序。当前只有结构差异复现，没有真实模型提前停止的证据。

### P3：工具文本块数组被序列化为 JSON 包装

位置：`crates/core/src/protocol.rs:147`。

对 `[{type: input_text, text: line1}, ...]` 形式输出，当前转为完整 JSON 字符串。内容未丢失，但模型收到额外协议包装。建议只对明确支持的文本块做文本提取；真实 JSON 字符串和对象仍需保真，不能泛化成删除所有 JSON 结构。

### P3：后续维护

- 将 App 中保存/启用/启动流程与展示组件逐步分离；避免只为了拆文件机械搬运状态。
- 将网关压缩在宏中的流转发循环拆成可单独验证的解析/转发步骤。
- 初次 snapshot 失败增加显式重试入口。
- 增加基于内存 bridge 的视觉基线，覆盖深色、长名称、最小窗口和弹窗。现有 CI 的单元测试与构建不能发现所有布局问题。
