# 统一当前配置与开启期间的约束

本说明替代当天较早版本中「旧会话继续使用历史路由」「开启期间允许编辑并等待应用」的规则。

## 产品规则

- 关闭时维护配置并勾选准备使用的配置。保存不自动开启。
- 至少选中一个配置才能开启；开启后至少保留一个，不能全部取消。
- 开启期间勾选变更和托盘切换立即应用，失败保留原选择及路由。
- 开启期间禁止新增、编辑和删除配置，界面有提示并禁用入口，原生命令也在操作锁内检查。已经打开的表单在托盘开启后同样锁定。
- 保存修改并重新开启后，新旧会话的后续请求统一使用当前配置。已发出的请求完成原有调用，不强制中断。
- 原模型仍存在于同一配置时，旧模型标识指向该模型的当前版本；原模型已删除或配置不再选中时，指向第一个选中配置的第一个模型。
- 恢复后台连接使用当前选择。Codex 的旧界面标签可能暂不变，重新打开用于刷新目录；路由切换本身不等待重启。

## 实现与验证边界

历史路由仅保留标识和配置归属，用于查找当前目标；后台不读取历史凭据或连接旧地址。映射随当前路由原子发布，当前模型目录仅包含已选模型。重新创建网关时同样加载标识映射，避免进程恢复后旧标识重新绑定旧服务。

跨厂商时，旧响应 ID 不直接转发给新服务。Chat 与 Responses 的已完成响应均可进入本地上下文缓存，Responses 流保持原始输出并捕获完成事件。缓存缺失或过期时明确报错，不回退到旧厂商。缓存沿用最多 64 条、1 小时、单项 1 MiB 的限制，不跨进程保存；仅有失效响应引用或服务专有上下文时，仍可能需要完整上下文或新任务。

历史数据库修订与系统凭据暂不自动删除，但不再作为活跃路由使用。删除配置不等于彻底擦除本地密钥。

验证覆盖：开启时的编辑锁与非空选择、切换失败回滚、已打开表单的托盘锁定、跨厂商旧标识更新、同配置模型的新 Key 修订映射、重复切换、网关重建标识映射，以及流式 Responses 上下文重建。

验证结果：前端 31 项、Rust 核心 82 项、托盘逻辑 2 项测试通过；TypeScript、Astro、Clippy（警告视为错误）、官网 15 页链接检查及密钥扫描通过。

仅使用模拟状态、临时目录和内存数据库测试。未运行真实 Codex App、读写真实配置或 Keychain，也未调用真实模型服务。单元测试和构建不代表真实 Codex 会话及各厂商的实机兼容性已验证。
