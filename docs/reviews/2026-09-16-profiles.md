# 配置实体与多模型管理重构

> 本文是早期实现记录。开启期间的编辑、勾选和历史会话规则已由[统一当前配置](2026-09-16-current-config.md)替代。

## 当前产品行为

- 首页以配置为单位，支持跨厂商多选，以及逐条编辑、删除。
- 一个配置有全局唯一名称、一个当前凭据标识、1–20 个模型；模型共用地址、接口和上下文设置。
- 新增默认名称按厂商计数生成：Kimi、Kimi-2、Kimi-3；跳过已占用名称。前后端检查首尾空白和大小写归一后的重名。
- 保存时验证所有模型，保存成功回首页，不自动勾选或应用，不启动 Codex。
- 勾选只保存待应用选择；点击应用后，所有所选配置的模型进入模型目录。显示名称为 `配置名称-模型`，请求路由仍使用不可混淆的内部标识。
- 已开启配置有未应用修改时显示「待应用」。打开应用与应用配置是独立操作；运行中重新加载需要正常重启确认。

## 数据与凭据

新增 `profiles` 表保存配置当前版本，模型路由保存在 `connections`，`route_keys` 映射到配置当前或历史凭据版本。凭据值仍只存系统凭据库。

保存一个配置只写一份当前 Key；修改 Key 生成新的凭据版本，所有新模型路由指向同一份 Key。修改模型集合保留仍可复用的路由标识，新模型分配新标识。配置 ID 保持稳定，不在首页留下多条修订记录。

配置及模型路由在单个 SQLite 事务中保存。先通过全部验证，再写凭据和元数据；数据库失败按原有补偿策略清理本次新增凭据。回滚失败会明确报告需要清理的凭据标识。

旧版单模型连接逐条迁移为配置，自动消除重名，保留路由和凭据标识；不比较或合并 Key，避免将不同账号误合并。迁移只在原生应用打开其数据库时发生，开发测试仅在临时数据库运行。

## 应用与历史会话

- `selected_profiles` 为待应用选择；`applied_routes` 为上次实际应用的完整路由快照。
- 原子应用同时提交默认模型、端口、已应用快照和历史路由索引；失败保持原配置和运行状态。
- 恢复后台连接使用上次已应用快照，不悄悄应用编辑草稿。
- 新的文件目录与 `/v1/models` 只展示本次应用的模型。历史别名保留用于旧会话，但不会重新出现在新目录中。
- 从未应用过的未勾选配置不会被加载成历史路由。
- 删除移除首页配置和待应用勾选；历史路由及凭据继续保留。删除并非彻底清除密钥，界面与隐私文档已说明。完全清理需用户先恢复配置并退出应用后处理本地数据和系统凭据。
