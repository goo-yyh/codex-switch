总开关位于首页底部的连接控制区。先在卡片中勾选需要提供给 Codex 的配置，再开启总开关。配置较多时卡片区独立滚动。开启后主界面显示蒙层，只保留「关闭服务」操作。

## 托盘快速操作

关闭主窗口后，可以通过菜单栏／系统托盘中的 Codex Switch 图标操作：

- **开启 Codex Switch**：应用首页已勾选的配置，可同时包含多个厂商。
- **关闭并恢复原配置**：恢复本次开启前的配置，与蒙层中的「关闭服务」一致。
- **选择配置（可多选）**：勾选或取消多个已保存配置，与首页同步。服务关闭时仅保存选择，点击下方「开启 Codex Switch」才会开启；服务已开启时，配置选择入口及所有配置项均禁用。
- **恢复后台连接**：按当前选中的配置重新建立路由。恢复操作沿用当前配置，不修改选择或设置。
- **退出应用**：右键点击托盘图标即可找到。先恢复原配置，再退出；如果 Codex 仍在使用本地连接，会提示先退出 Codex。

macOS 托盘的配置列表支持连续勾选或取消：点击后菜单保持展开，选择立即保存，不会自动开启服务。

菜单中的勾号表示当前所选配置，服务关闭后仍保留。没有配置时，请先打开主界面添加。

切换失败时保留原状态，并打开主界面显示原因；关闭服务时自动恢复原配置，无需再次确认。如果有外部修改，会先另存副本。切换成功后，旧会话的后续请求也使用当前配置。菜单和主界面会提示重新打开以刷新模型列表；关闭后的原设置可能需要重新打开才能被 Codex 读取。不会自动重启或结束任务。

## 开启

1. 读取当前 `config.toml`，保存其原始内容和是否存在的状态。
2. 先将恢复记录写入 Codex Switch 的本地数据目录。
3. 原子写入本地路由与模型目录配置。

至少选中一个配置才能开启。开启期间主界面显示不可跳过的蒙层，只保留「关闭服务」。配置选择、新增、编辑、删除和通用设置都需要先关闭服务；托盘中的配置选择也会禁用。重复开启或切换配置不会覆盖这次开启时保存的最早备份。

## 关闭

关闭服务后恢复 **这次开启之前** 的文件内容，包括原有注释和换行。原先没有 `config.toml`，则删除本次创建的文件。下一次开启会重新保存当时的配置。

Codex Switch 不修改 `auth.json`、会话或历史记录。恢复针对 `config.toml`，不会把整个 Codex 目录替换为旧副本。

## Codex 仍在运行

文件恢复后，正在运行的 Codex 可能仍使用内存中的旧配置。应用会提示重新打开，并暂时保留本地路由，以免突然切断当前请求。正常退出 Codex 后再打开，使用恢复后的配置。

## 其他程序修改了配置

关闭服务时会自动恢复开启前的配置，无需再次确认。若检测到开启后的外部修改，会先把当前文件另存到应用数据目录，再恢复原始备份。另存失败时会保留当前文件并显示错误。

## 应用异常退出

恢复记录在写入 Codex 配置前落盘。重新打开 Codex Switch 后，可从托盘选择「恢复后台连接」。此操作只重新建立本地路由，不会打开或重启 Codex；也可以点击蒙层中的「关闭服务」恢复原配置。正在运行的 Codex 可能需要正常退出后再打开才能读取新连接。异常退出期间路由不可用；第一版不会在后台偷偷启动或重启 Codex。

## 备份在哪里

恢复记录：应用数据目录下的 `activation.json`。冲突时保留的文件：`before-restore-<编号>.toml`。macOS 通常位于 `~/Library/Application Support/com.codexdocs.switch/`，Windows 使用系统应用数据目录。

备份可能包含原配置里已有的敏感字段，请保留在本机。不要在问题反馈中上传完整备份。

## 切换失败与目录清理

开启或切换失败时，会恢复本次操作前的配置，保持已有路由和默认选择。同次开启的最初备份仍用于关闭恢复。如果此时检测到其他程序修改配置，则保留该修改并提示冲突。

Codex 未运行且没有请求时，会清理不再被当前配置或恢复基线引用的自动生成模型目录。勾选配置中有密钥不可用时，本次应用失败并保留原状态；未勾选配置不会进入新模型目录。恢复后台连接按当前选中的配置建立路由。旧模型标识只用于兼容旧会话，不再指向历史 Key 或地址：同一配置仍有原模型时使用最新版本，否则使用当前默认模型。
