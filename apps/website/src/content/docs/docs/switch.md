总开关位于首页底部的连接控制区。先在卡片中勾选需要提供给 Codex 的配置，再开启总开关。配置较多时卡片区独立滚动，开关与打开按钮保持可见。

## 托盘快速操作

关闭主窗口后，可以通过菜单栏／系统托盘中的 Codex Switch 图标操作：

- **开启所选配置**：应用首页已勾选的配置，可同时包含多个厂商。
- **关闭并恢复原配置**：恢复本次开启前的配置，与首页关闭开关一致。
- **切换并开启配置（单选）**：点选一个已保存配置，直接应用它的全部模型，并同步首页勾选。若原来已关闭，会同时开启。需要同时使用多个配置时，请在首页勾选后应用。
- **恢复后台连接**：按当前选中的配置重新建立路由。开启期间不能编辑配置，勾选变更直接应用，不再有待应用版本。
- **退出 Codex Switch**：右键点击托盘图标即可找到。先恢复原配置，再退出；如果 Codex 仍在使用本地连接，会提示先退出 Codex。

菜单中的勾号表示当前已应用的配置版本，不代表首页尚未应用的选择。没有配置时，请先打开主界面添加。

切换失败时保留原状态，并打开主界面显示原因；恢复遇到外部修改时，需要在主界面处理冲突，托盘不会强制覆盖。切换成功后，旧会话的后续请求也使用当前配置。菜单和主界面会提示重新打开以刷新模型列表；关闭后的原设置可能需要重新打开才能被 Codex 读取。不会自动重启或结束任务。

## 开启

1. 读取当前 `config.toml`，保存其原始内容和是否存在的状态。
2. 先将恢复记录写入 Codex Switch 的本地数据目录。
3. 原子写入本地路由与模型目录配置。

至少选中一个配置才能开启。开启期间更改勾选立即应用，不能取消最后一个配置；新增、编辑和删除都需要先关闭。重复开启或切换配置不会覆盖这次开启时保存的最早备份。

## 关闭

关闭开关后恢复 **这次开启之前** 的文件内容，包括原有注释和换行。原先没有 `config.toml`，则删除本次创建的文件。下一次开启会重新保存当时的配置。

Codex Switch 不修改 `auth.json`、会话或历史记录。恢复针对 `config.toml`，不会把整个 Codex 目录替换为旧副本。

## Codex 仍在运行

文件恢复后，正在运行的 Codex 可能仍使用内存中的旧配置。应用会提示重新打开，并暂时保留本地路由，以免突然切断当前请求。正常退出 Codex 后再打开，使用恢复后的配置。

## 其他程序修改了配置

检测到开启后的外部修改时，不会直接覆盖。你可以保留现状，或者选择「备份并恢复」。后者会先把当前文件另存到应用数据目录，再恢复原始备份。

## 应用异常退出

恢复记录在写入 Codex 配置前落盘。重新打开 Codex Switch 后，首页显示「恢复连接」入口。点击它只重新建立本地路由，不会打开或重启 Codex；也可以关闭开关恢复原配置。正在运行的 Codex 可能需要正常退出后再打开才能读取新连接。异常退出期间路由不可用；第一版不会在后台偷偷启动或重启 Codex。

## 备份在哪里

恢复记录：应用数据目录下的 `activation.json`。冲突时保留的文件：`before-restore-<编号>.toml`。macOS 通常位于 `~/Library/Application Support/com.codexdocs.switch/`，Windows 使用系统应用数据目录。

备份可能包含原配置里已有的敏感字段，请保留在本机。不要在问题反馈中上传完整备份。

## 切换失败与目录清理

开启或切换失败时，会恢复本次操作前的配置，保持已有路由和默认选择。同次开启的最初备份仍用于关闭恢复。如果此时检测到其他程序修改配置，则保留该修改并提示冲突。

Codex 未运行且没有请求时，会清理不再被当前配置或恢复基线引用的自动生成模型目录。勾选配置中有密钥不可用时，本次应用失败并保留原状态；未勾选配置不会进入新模型目录。恢复后台连接按当前选中的配置建立路由。旧模型标识只用于兼容旧会话，不再指向历史 Key 或地址：同一配置仍有原模型时使用最新版本，否则使用当前默认模型。
