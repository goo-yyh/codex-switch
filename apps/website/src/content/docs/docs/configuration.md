一个配置保存一个 API Key 和 1–20 个模型。各模型默认使用外层连接信息，也可单独覆盖地址、接口格式和能力。

## 连接信息

| 字段            | 用法                                                                                      |
| --------------- | ----------------------------------------------------------------------------------------- |
| 服务 / 服务套餐 | 为新配置填入初始地址、接口、模型和能力。切换套餐会重置这些初始值并清空待填写的 Key。      |
| 配置名称        | 用于首页识别，也作为 Codex 模型显示名称的前缀。不能与其他配置重名，忽略首尾空格和大小写。 |
| API 地址        | 填写服务的基础地址；路径前缀会保留。详见[地址示例](/docs/relay/#地址怎么填)。             |
| 完整 URL        | 开启后普通请求直接发往所填 URL，不追加接口路径。                                          |
| 接口格式        | 选择目标服务支持的 Responses 或 Chat Completions。                                        |
| API Key         | 此配置内所有模型共用的密钥，保存在系统凭据库。不同 Key 应分别新建配置。                   |

同厂商可保存多个配置，默认名称依次为 `Kimi`、`Kimi-2` 等，也可自行修改。已保存配置不能直接换厂商，如需更换请新增配置。

编辑已有配置时，Key 留空可保留原密钥。改变请求地址（包括单个模型的地址）或完整 URL 模式，需要重新填写对应 Key。地址输入框里不要放密钥。

## 模型选择与默认模型

第一个勾选的模型为默认模型，也可在其他已选模型后点击「设为默认」。移除默认模型后，剩余模型中的第一个接替。自定义模型需填写服务商的准确模型 ID，不填写展示名称。

模型旁的「已配置」表示其他配置已使用相同厂商、地址与接口下的这个模型，并不禁止重复选择，也不会删除其他配置。

## 逐模型编辑

选中模型后点击「编辑」，弹窗的修改仅作用于当前配置的这个模型。**点击「确认修改」后，还需点击表单底部「保存配置」。**

[![模型编辑弹窗：地址、接口、上下文长度、思考档位、图像输入与并行工具调用](/screenshots/model-options.png)](/screenshots/model-options.png)

_当前应用浏览器预览截图，使用示例配置。_

| 设置                           | 含义                                                                                          |
| ------------------------------ | --------------------------------------------------------------------------------------------- |
| API 地址 / 接口格式 / 完整 URL | 未覆盖时继承外层配置；「继承外层设置」可清除这三项覆盖。地址留空仍继承外层地址。              |
| 上下文长度                     | 向 Codex 声明模型的上下文容量，单位为 token，允许 4,096–2,000,000。填大不会扩大上游实际容量。 |
| 思考档位                       | 以英文逗号分隔支持的档位，例如 `low,high,max`。只填服务实际支持的值。                         |
| 默认思考档位                   | 必须属于已填写的思考档位列表。                                                                |
| 图像输入                       | 按模型注册表判断，或手动声明文本 / 文本与图像。开启声明不会使纯文本模型获得视觉能力。         |
| 并行工具调用                   | 按默认值，或显式声明支持 / 不支持。实际行为仍取决于服务与模型。                               |

思考档位可用值为 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`、`ultra`，并非每个模型都支持所有档位。能力未覆盖时使用预设或模型目录默认值。

例如，外层使用 Responses，某个模型仅提供 Chat 接口，可只在该模型中覆盖接口格式。若它还需要不同地址，可同时覆盖地址；两个模型仍使用同一个 Key，需要不同密钥时应拆成两个配置。

## 保存、测试与生效

### 上下文预留

内置模型的上下文预设按官方容量的 **80% 向下取整**，为请求和输出预留余量。例如 1,000,000 → 800,000，262,144 → 209,715，204,800 → 163,840。每个模型单独设置，不继承同厂商旗舰模型的较大容量。智谱 1M 文档示例存在差异，预设保守按 1,000,000 计算。

Kimi Coding 套餐的 `k3` 默认按 Moderato 的 256K 权益设置为 209,715；Allegretto 及以上可改为 838,860。`k3-256k` 固定使用 209,715；`kimi-for-coding` 当前对应 K2.8 Preview，预设为 838,860。依据：[官方套餐规格](https://www.kimi.com/code/docs/kimi-code/models.html)。

新配置或重新选择套餐时载入新预设。已有配置的上下文值保持不变，需要在模型编辑中手动调整；保存和启用不会再次乘 80%。这个值是声明给 Codex 的上下文容量，实际自动压缩时机仍由 Codex 决定，预留余量不保证所有请求都不会超限。

### 操作说明

- **保存配置**：只保存当前内容，不发测试请求、不自动勾选或开启。
- **测试配置**：逐个使用模型最终生效的地址和接口，检查基础文本响应；不会保存或开启。可取消测试，测试期间不能修改字段或离开表单。
- **开启 Codex Switch**：将所选配置的模型应用到 Codex。编辑配置前需先关闭，保存后再开启。

同时选中多个配置时，每个配置的模型都会显示在 Codex 中。请求失败不会自动尝试其他配置；已有任务切换后的路由行为见[开启、关闭与恢复](/docs/switch/)。

## 思考档位默认值

模型能力弹窗会读取对应模型和套餐的思考预设，已有配置缺失的字段也会补齐；已填写的值保持不变。默认值按官方说明设置，不统一为 high。GLM 5.3/5.2、普通 API 的 Kimi K3 默认 max；Kimi Coding 的 k3/k3-256k 默认 high，kimi-for-coding 默认 max。千问 3.8 默认 xhigh，已明确公布的 3.7/3.6 型号使用 medium；DeepSeek 默认 high。

MiniMax M3 的普通 Responses API 默认 none，官方 Codex 套餐示例使用 high。对于仅支持思考开关的模型，界面会说明 none/high 表示关闭/开启，并非原生强度等级。未查到官方单独默认值的型号保留自动选择。
