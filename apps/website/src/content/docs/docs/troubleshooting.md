## 连接测试失败

| 现象               | 检查方式                                   |
| ------------------ | ------------------------------------------ |
| 401 / 403          | 密钥是否有效，是否属于当前套餐 / 节点      |
| 404                | API 地址、路径前缀、模型 ID 是否正确       |
| 429                | 服务商额度与限流状态                       |
| 400 / 422          | 模型是否支持该接口和请求参数               |
| 超时               | 本机网络及服务可用性                       |
| 已响应但无完整文本 | 可能只有推理输出、预算不足或返回格式不兼容 |

应用不会显示完整供应商错误响应，防止错误中夹带密钥或请求内容。请优先在供应商控制台核对状态。

## 开启后 Codex 没变化

Codex 可能尚未重新读取配置。先完成任务，正常退出后通过 Codex Switch 打开。已有任务的标签可能保留旧名称，但经过当前本地路由的后续请求使用当前配置；模型列表可能需要重新打开才能刷新。

## 提示配置被其他程序修改

选择保留现状，或「备份并恢复」。后者会保留后续修改副本，再恢复开启前版本。[恢复规则](/docs/switch/)

## 本地端口被占用

应用会停止开启，不会覆盖配置。请退出占用该端口的已知程序后重试。不要盲目终止不认识的进程。

## 无法删除连接

开启期间禁止新增、编辑或删除配置。先关闭 Codex Switch，再进行修改；没有选中配置时无法重新开启。

## 应用意外退出后不能连接

重新打开 Codex Switch，点击「恢复连接」并按提示重新打开 Codex，或关闭总开关恢复原配置。第一版缓存不会跨进程保存，旧的会话引用可能需要新建任务。

## 切换后提示会话缓存失效

请求已经切换到当前配置，不会回退使用旧服务。会话上下文缓存在内存中，最多保留 64 条响应、1 小时，且有大小限制；退出或异常重启后不会保留。若客户端仅发送旧响应引用而未提供完整上下文，无法重建时会明确报错，需要提供完整上下文或新建任务。不同服务的专有上下文格式也可能不兼容。

## 模型设置与外层配置不一致

模型可单独覆盖 API 地址、接口和完整 URL 模式。打开该模型的「编辑」检查，或点击「继承外层设置」清除连接覆盖，再确认并保存。手动测试也使用模型最终生效的设置。[字段说明](/docs/configuration/)

## 压缩失败或开关不能修改

远程上下文压缩需要上游支持，建议保持关闭；普通摘要请求不需要打开此开关。请先关闭首页总开关再修改，偏好自动保存，下次开启时生效。[通用设置](/docs/settings/)

## 如何反馈

到 [GitHub Issues](https://github.com/goo-yyh/codex-switch/issues) 提供操作系统、版本、服务名称、接口格式和脱敏错误。不要上传 `.env`、完整配置、API Key 或私有任务内容。
