---
title: 三步连接
description: 新增配置、勾选配置并在 Codex 中使用多个模型。
---

## 1. 新增配置

新增、编辑和删除需要先关闭 Codex Switch。开启期间仅允许切换已保存的配置。

在首页点击「新增配置」，选择厂商或coding plan，填写配置名称和一个 API Key，勾选一个或多个模型。

配置名称默认使用厂商名称，例如 `Kimi`；同厂商再次添加时依次使用 `Kimi-2`、`Kimi-3`，自动跳过已经占用的名称。名称可以修改，但不能与其他配置重名（忽略首尾空格和大小写）。同厂商的多个配置可以使用不同 Key。

一个配置中的所有模型共用这个 Key、API 地址、接口格式；上下文与其他能力可逐模型覆盖。没有列出的模型可以输入 ID 后点击「添加模型」或回车。使用 Coding Plan、海外节点或企业网关时，在「连接信息」选择或核对套餐地址。

第一个勾选的模型为该配置的默认模型，也可以在其他已选模型后点击「设为默认」。取消勾选或删除默认模型后，使用剩余已选模型中的第一个。自定义模型后提供删除入口；模型 ID 去除首尾空格后不能与当前列表中的 ID 重复。不同配置可以使用相同模型。

## 2. 保存后回到首页

底部固定显示「测试配置」和「保存配置」。点击「保存配置」直接保存为**一个配置**并回到首页，不自动发送请求。需要检查连通性时，手动点击「测试配置」；应用逐个请求所选模型，显示成功或失败结果，不会自动保存。

保存不会自动勾选配置、启用路由或打开 Codex。编辑已有配置时可以调整名称、模型列表和 Key；Key 留空会保留当前配置的密钥，更改 API 地址时必须重新填写。已有配置不能更换厂商，如需使用其他厂商请新增配置。

## 3. 勾选并应用

首页列出所有配置及各自的模型，可同时勾选不同厂商的多个配置。至少勾选一个配置后，开启首页底部的「Codex Switch」总开关。应用会备份原配置，并把**所有勾选配置中的模型**放入 Codex 的模型目录。

关闭时可以自由勾选，未选中任何配置时无法开启。开启后更改勾选会立即应用，至少保留一个配置；最后一个选中项不能取消。如需停用或修改配置内容，请先关闭总开关。切换失败时保留原选择。

点击「打开 Codex」。如果 Codex 已在运行且配置需要重新加载，完成当前任务后点击「重新打开 Codex」并确认正常重启。应用不会强制结束正在执行的请求。

## Codex 中如何显示

显示名称为 `配置名称-模型`。例如：

| 配置     | 模型           | Codex 中显示          |
| -------- | -------------- | --------------------- |
| 工作账号 | glm-4.7        | `工作账号-glm-4.7`    |
| 工作账号 | glm-5          | `工作账号-glm-5`      |
| Kimi     | kimi-k2.7-code | `Kimi-kimi-k2.7-code` |

同时勾选「工作账号」和「Kimi」后，可以在 Codex 的模型列表中选择这三个模型。应用时使用第一个勾选配置的默认模型，其他模型仍会显示在目录中。

## 编辑、删除和旧配置

关闭 Codex Switch 后，每个配置可编辑、删除。保存后重新开启，旧会话与新会话的后续请求统一使用当前选中的配置。旧会话的原模型仍存在于同一配置时使用其最新版本；已移除或取消选择时转到当前默认模型。已发出的请求正常完成，不强制中断。

例如从 GLM 切换到 Kimi 后，旧 GLM 会话的下一次请求也走 Kimi，不再调用旧 GLM Key。旧会话中的模型标签可能仍显示旧名称；重新打开 Codex 可刷新模型列表，但无需为切换路由强制重启。

旧版本按模型保存的连接会逐条迁移为独立配置，保留原模型和凭据，并自动处理重名。不会仅因厂商相同就合并旧连接，避免混用不同 Key。

测试期间不能离开表单、保存或修改字段，可以点击「取消测试」。测试成功、失败或取消都不会自动保存、应用或打开 Codex。
