当前版本为开发预览。协议转换、本地测试和供应商 HTTP 检查各有不同边界，不能把“模型能返回文本”当作“完整 Codex App 兼容”。

## 接口能力

| 能力                    | 原生 Responses 上游        | Chat Completions 上游                 |
| ----------------------- | -------------------------- | ------------------------------------- |
| 文本与流式文本          | 转发                       | 本地转换                              |
| 函数工具与工具结果      | 转发                       | 支持格式转换与多轮历史                |
| Namespace / Custom 工具 | 转发，依赖上游             | 展平 / JSON 包装后还原                |
| 图片输入                | 按模型能力转发             | 按模型声明转换                        |
| 托管网页搜索等工具      | 依赖上游，未启用           | 拒绝并说明                            |
| 普通文本摘要            | 作为普通请求转发           | 走普通 Chat 转换                      |
| 远程压缩                | 开关启用后透传，需上游支持 | 不支持 Remote V2 触发项及加密压缩历史 |
| WebSocket               | 未启用                     | 未启用                                |
| 请求失败后自动切换      | 不支持                     | 不支持                                |

模型目录参考、复用 CC Switch 的模板与能力注册表，并由本项目维护预设。可[逐模型覆盖能力](/docs/configuration/)，但声明能力不会改变上游实际支持范围。

## 远程压缩与普通摘要

[远程上下文压缩](/docs/settings/#远程上下文压缩)默认关闭，建议保持关闭。关闭后仍可通过普通模型请求生成文本摘要。

开启后由 Codex 选择远程协议。原生 Responses 路由透传 Remote V2 的 `compaction_trigger`、压缩项，以及旧版 `/responses/compact` 请求；服务是否支持需单独确认，不保证失败时自动回退。

Chat 路由明确拒绝 Remote V2 触发项和不透明的加密压缩历史。旧版 Chat compact 虽沿用上游普通转换路径，也不等于实现了远程压缩契约；不会伪造加密压缩项。

## 普通摘要生成验证

2026-09-17，向五家当前预设默认模型各发送 **一次普通 Responses 流式请求**，使用约 128 KB 合成历史，输出上限 2,048 tokens。

| 模型                | 结果                          |
| ------------------- | ----------------------------- |
| `qwen3.8-max`       | HTTP 200、completed、非空摘要 |
| `MiniMax-M3`        | HTTP 200、completed、非空摘要 |
| `glm-5.3`           | HTTP 200、completed、非空摘要 |
| `kimi-k3`           | HTTP 200、completed、非空摘要 |
| `deepseek-v4-flash` | HTTP 200、completed、非空摘要 |

五项均满足流式文本与最终文本一致，且摘要短于输入。完整范围见[最小摘要验证报告](https://github.com/goo-yyh/codex-switch/blob/main/docs/testing/provider-summary-smoke-2026-09-17.md)。

此检查**没有启动 Codex App，也没有调用远程 compact**；不验证摘要事实完整性、续接召回、自动触发或指令重新注入。它不覆盖全部候选模型、Coding Plan、海外节点与企业网关。

其他历史接口结果见仓库[测试记录目录](https://github.com/goo-yyh/codex-switch/tree/main/docs/testing)。结果只适用于记录的日期、模型、地址与测试项目，预设更新不继承旧模型的测试结论。

## 本地会话缓存

Chat 转换的历史与工具元数据只保存在进程内存中，最多 64 条、每条最多 1 MiB、有效期 1 小时，按连接隔离。支持 `previous_response_id` 和同一连接内唯一 `call_id` 补全，也支持客户端回传完整工具历史。

调用标识冲突时拒绝猜测。重启、超时或淘汰后，无法补全的引用会明确报错，应重新开始任务。不会从磁盘读取 Codex 历史来补全请求。

## 尚未验证的部分

离线测试使用临时目录、模拟凭据与合成请求；供应商测试是独立、显式执行的 HTTP 检查。当前没有真实 Codex App 长任务端到端验证，也没有 Windows 实机验证结论。正式分发的签名与公证仍待完成。
