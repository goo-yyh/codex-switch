## 第一版边界

| 能力                    | 原生 Responses 上游 | Chat 上游              |
| ----------------------- | ------------------- | ---------------------- |
| 文本与流式文本          | 转发                | 本地转换               |
| 函数工具与工具结果      | 转发                | 支持格式转换与多轮历史 |
| Namespace / Custom 工具 | 转发，依赖上游      | 展平 / JSON 包装后还原 |
| 图片输入                | 按模型能力转发      | 按模型声明转换         |
| 托管网页搜索等工具      | 依赖上游，未启用    | 拒绝并说明             |
| 远程压缩                | 开关启用后透传 compact | 沿用 CC Switch 转换路径，需 App 验证 |
| WebSocket               | 未启用              | 未启用                 |
| 响应开始前故障转移      | 用户配置的有序队列  | 用户配置的有序队列     |

模型目录复用 CC Switch 的原生/Chat 模板、DeepSeek 官方目录与模型能力注册表，允许逐模型覆盖上下文、思考档位、图像和并行工具能力。模型别名用于区分同名模型的不同连接，避免把旧任务发送到错误服务。

远程压缩在「通用设置」中默认关闭。开启采用 CC Switch 相同的自定义 provider 标记，使 Codex 尝试远程压缩；不代表上游一定支持。Chat compact 不再直接 501，也不会伪造加密内容，当前没有真实 App 长任务验证。

## 本地会话缓存

Chat 转换的历史与原始工具元数据只保存在进程内存中，每条最多 1 MiB、最多 64 条、有效期 1 小时，按连接隔离。支持 `previous_response_id` 和同一连接内唯一 `call_id` 补全，也支持客户端回传完整工具历史。调用标识冲突时拒绝猜测。应用重启、超时或淘汰后，无法补全的引用会明确报错，应重新开始任务。不会从磁盘读取 Codex 历史来补全请求。

## 验证分层

- **单元测试**：临时目录与内存组件，验证文件恢复、协议转换、缓存隔离等。
- **供应商测试**：显式读取 `.env`，仅向预设供应商发送少量 HTTP 请求。
- **Codex App 实机测试**：当前刻意不运行，避免影响开发者本地使用。

因此，当前版本是开发预览，并未宣称五家服务在 Codex App 中全部通过端到端验证。Windows 实机、发布签名及公证也需要发布前补充验证。
